## Notes and Caveats

- **Claims 1–3 (Surveys)**: The 10th annual *2025 State of Rust Survey* ran Nov 17 – Dec 17, 2025 and published results on `2026-03-02`; no 2026 annual survey results exist yet as of `2026-11-16`. Similarly, the *2025 Compiler Performance Survey* results (`2025-09-10`) remain the most recent compiler-performance survey. Notably, a separate Rust Vision Doc interview synthesis published `2026-03-20` (`raw/recency/2026-11-16-rust-challenges-2026.md`) remarked that among interviewees nobody said compile time *currently* blocked them, though enterprise users worried about scaling as Rust codebases grow.
- **Claim 4 (`rust-lld` on Linux)**: Shipped in Rust `1.90.0` (`2025-09-18`, `raw/recency/2026-11-16-rust-1-90-0-blog.md`) and remains the default in Rust `1.100.0` (`2026-11-12`). Other Linux targets (such as `aarch64-unknown-linux-gnu`) still default to the system linker as of Rust `1.100.0` (`raw/recency/2026-11-16-cargo-build-performance.md`).
- **Claims 5–7 (Cranelift backend)**: `rustc_codegen_cranelift` remains nightly-only and requires `-Z codegen-backend` (`raw/recency/2026-11-16-cargo-build-performance.md`). **Claim 6 is `outdated`**: the 2025h2 `Production-ready cranelift backend` goal (`raw/recency/2026-11-16-goals-2025h2-production-ready-cranelift.md`) was replaced in the 2026 Project Goals by `Improve rustc_codegen_cranelift performance` (`rust-lang/goals#639`), targeting a 2x internal speedup via in-memory function caching, JIT, or IR interpretation. **Claim 7 is `refuted`** (and supersedes the 2025h2 framing): the 2025h2 goal cited ~20% codegen-time reduction (~5% clean-build total) on local builds of Zed/Tauri/hickory-dns, whereas `@bjorn3`'s 2026 goal (`2026-08-24`) reports that on the Rust project's `rustc` benchmark suite (`perf.rust-lang.org`) with `-Cdebuginfo=line-tables-only`, Cranelift averages a **10–15%** single-crate compilation speedup (ranging from negligible to ~30%), and **5%–12%** start-to-finish incremental speedup on Zed as of February 2026.
- **Claim 8 (Parallel front end)**: Remains nightly-only and disabled on **stable** Rust `1.100.0`. However, two major changes landed in late 2026: (1) on **nightly and dev** channels, `rust-lang/rust#162848` (merged `2026-09-16`) enabled **2 parallel frontend threads by default**; and (2) `rustc` introduced unstable `--jobs-frontend` / `--jobs-backend` flags (`rust-lang/rust#160697`, `#165556`) with `-Z threads`'s internal help text now pointing to `--jobs-frontend`.
- **Claims 9–11 (Wild linker)**: Actively maintained under its new GitHub org `wild-linker/wild`, releasing `0.8.0` (`2026-01-16`), `0.9.0` (`2026-05-23`), `0.10.0` (`2026-08-04`), and `0.11.0` (`2026-10-24`). On Wild 0.11.0's Ryzen 9 9955HX Linux benchmarks (`raw/recency/2026-11-16-wild-chrome-crel-svg.md`), Mold `3.0.0` is `+26%` slower on `chrome-crel` (and `+16%` on `chrome`, `+324%` on `bevy-dylib`, `+3%` on `clang-debug`). **Caveat on Claim 9**: in `2026-09-18` (`raw/recency/2026-11-16-wild-vs-mold-2026-09-18.md`), Wild author David Lattimore showed that after Mold `2.42.x` speedups, Wild `0.10.0` was 1.2x *slower* than Mold on fresh-file `ext4` `--no-fork` debug links (`blender-debug`, `godot-debug`), while faster (`0.6x–0.9x`) on `tmpfs` and existing-output-file links; Wild `0.11.0` subsequently added `fallocate`, hugepages, and a 32-thread cap. **Claim 11 is `outdated`**: Wild `0.11.0` (`2026-10-24`) enabled **WebAssembly (`wasm32`)** linking by default (`raw/recency/2026-11-16-wild-readme.md` lists `WebAssembly (wasm32)` under supported platforms), and its experimental macOS Mach-O port can already self-link Wild on macOS (though not yet enabled by default; Windows remains unsupported).
- **Claims 12–14 (`rustc` experimental incremental/unused flags)**: Relink Don't Rebuild (`-Z public-api-hash`, `rust-lang/rust#158844`, PR `#156940`) is an accepted 2026 goal targeting nightly in 2026 and stabilization prep in 2027 (`raw/recency/2026-11-16-goals-2026-roadmap-fast-builds.md`). `-Z hint-mostly-unused` remains unstable in both `rustc` and Cargo (`profile-rustflags` / Cargo `hint-mostly-unused`). `-Z cache-proc-macros` (`rust-lang/rust#151364`, updated `2026-01-19`) exists on nightly, but currently caches **derive** proc-macro invocations only and does not verify macro purity.
- **Claims 15–16 (TPDE)**: TU Munich's TPDE CGO 2026 paper (`2026-01-16`) and docs confirm 10–20x compile speedups over LLVM `-O0`. For **Claim 16**, no TPDE backend is usable for general Rust projects via `rustup` today (`llvm.tpde = false` in `bootstrap.example.toml`, not enabled in CI/dist builds, ELF Linux-only, fails on inline asm/SIMD/sanitizers/LTO). **Major recency update**: under 2026 Project Goal `goals#802`, `rust-lang/rust#163731` (`2026-10-03`) added optional local TPDE bootstrap support and `rust-lang/rust#164108` (merged `2026-11-13`, three days ago, `raw/recency/2026-11-16-rust-pr-164108-llvm-tpde.md`) landed unstable `-Z llvm-tpde` (`try`/`only`), compiling 1,101 of 1,113 `ripgrep` CGUs via TPDE (falling back to LLVM on 12) for a preliminary 3–4% wall-time gain.
- **Claims 17–21 (Cargo locking, `build-dir`, worktrees, cross-workspace cache)**: Cargo `1.91.0` (`2025-10-30`) stabilized `build.build-dir`, and Rust `1.100.0` (`2026-11-12`, `rust-lang/cargo#17354`) stabilized the new v2 unit-scoped `build-dir` layout (`raw/recency/2026-11-16-rust-1-100-0-blog.md`). However, stable Cargo still holds an exclusive `.cargo-build-lock` on the build directory (`tests/testsuite/concurrent.rs`), `-Z fine-grain-locking` remains unstable and suffers from concurrent unit-lock deadlocks (`rust-lang/cargo#17508`, opened `2026-09-24`, `raw/recency/2026-11-16-cargo-issue-17508-locking.md`), default `target/` remains per-workspace/per-worktree, and Cargo's cross-workspace cache (`rust-lang/goals#626`, `cargo#5931`) is still nightly design/implementation work in 2026.
- **Claims 22–26 (Prebuilt deps, `sccache`, Bazel/Buck2, GC, `rust-cache`)**: Cargo still builds crates.io library dependencies from source (`rust-lang/cargo#1139` remains open in `S-needs-design`, `cargo-binstall` only installs binaries). `sccache` (`v0.19.0`, `2026-10-24`) still cannot cache incremental crates, though in 2026 it added `SCCACHE_ALLOW_INCREMENTAL=1` (caching non-incremental dependencies while leaving incremental workspace crates uncached) and `SCCACHE_BASEDIRS` (cross-checkout cache hits). Bazel (`rules_rust` `0.75.0`, `raw/recency/2026-11-16-rules-rust-home.md`) and Buck2 support RBE/remote caching natively while Cargo does not. Cargo's automatic GC (stabilized in `1.88.0`, `raw/recency/2026-11-16-rust-1-88-0-blog.md`) cleans only `$CARGO_HOME` global caches, not `target/` (`rust-1-100-0-blog.md` notes build-dir cache GC remains a future project). `Swatinem/rust-cache` (`v2.9.3`, `2026-10-20`, `1,967` GitHub stars vs `208` for `Mozilla-Actions/sccache-action`, `raw/recency/2026-11-16-swatinem-rust-cache-api.md`) remains the de-facto GitHub Actions cache.
- **Claims 27–32 (Inner loop & editor)**: Dioxus `subsecond` (`v0.7.10` on `2026-07-30`, `v0.8.0-alpha.3` on `2026-10-16`) hot-patches arbitrary Rust apps via `subsecond::call`, though loading patches still relies on a runner speaking its protocol such as `dioxus-cli` (`dx serve`). `watchexec/cargo-watch` remains archived (`2025-01-18`) recommending `Canop/bacon` (`3,478` stars, updated `2026-11-04`). `cargo-nextest` (`0.9.152`, `2026-11-13`) is actively maintained and advertises up to 3x faster runs than `cargo test`. `rust-analyzer.cargo.targetDir` still defaults to `null` as of `2026-11-16` (`crates/rust-analyzer/src/config.rs`), sharing `target/` and contending on Cargo's lock unless configured. `cargo-wizard` (`v0.2.3`, `2026-04-13`) remains active. Bevy (`v0.20.1`, `2026-10-28`) still recommends `bevy/dynamic_linking` in both its Setup guide (`raw/recency/2026-11-16-bevy-quickstart-setup.md`) and Fast Compiles page.
- **Claims 33–35 (AI-agent loop)**: Neither `rust-analyzer` (`#19608`, `#20340` closed as duplicate) nor Cargo (`raw/recency/2026-11-16-cargo-commands-mod-rs.md`) ships an official MCP server. Multiple third-party MCP servers exist (e.g., `zeenix/rust-analyzer-mcp` with `88` stars, `nazmulidris/rust-mcp`, `SignalWhisperer/cargo-mcp`). For **Claim 35**, a tool built *specifically* to speed up the Rust build loop for parallel AI coding agents finally appeared three weeks ago — **Ferry (`patwrall/ferry` / `ferry-rs`)**, first published `2026-10-24` — but with only **2 GitHub stars** as of `2026-11-16`, it is not yet widely adopted; widely adopted adjacent tools (`max-sixty/worktrunk` at `12,549` stars; `kunobi-ninja/kache` at `1,468` stars) are language-agnostic git-worktree or multi-language compiler-cache tools rather than Rust-specific agent build-loop tools.

## Not covered by the claims

Significant projects, tools, RFCs, project goals, and stable Rust/Cargo changes from the last 12 months (`2025-11-16` to `2026-11-16`) relevant to Rust compile times and developer experience that are not mentioned in the 35 claims:

### 1. Ferry (`ferry-rs`)
- **URL**: https://lib.rs/crates/ferry-rs
- **Description**: CLI that builds one warm Cargo base per commit and forks isolated, already-warm git worktrees (via reflinks/overlayfs and timestamp/path-remap handling) for parallel AI coding agents.
- **Date**: 2026-10-29
- **Current status**: Active, early alpha (`v0.1.3`, 2 GitHub stars; API unstable)
- **Source file**: `raw/recency/2026-11-16-ferry-rs-librs.md`
- **Verbatim quote**: "Ferry builds each commit once, then gives every agent its own fork of that warm build."

### 2. Kache (`kunobi-ninja/kache`)
- **URL**: https://raw.githubusercontent.com/kunobi-ninja/kache/main/README.md
- **Description**: Zero-copy, content-addressed compiler cache for Rust, C/C++, and CUDA that shares compiled outputs across git worktrees and CI runs without duplicating disk blocks.
- **Date**: 2026-11-12
- **Current status**: Active (`1,468` GitHub stars; requires Rust 1.95+)
- **Source file**: `raw/recency/2026-11-16-kache-readme.md`
- **Verbatim quote**: "Kache is a compiler cache for Rust, C/C++, and CUDA on Linux, macOS, and Windows. It restores matching compiler outputs across worktrees and CI runs, so you spend less time rebuilding and less disk space storing the same bytes."

### 3. Worktrunk (`max-sixty/worktrunk`)
- **URL**: https://raw.githubusercontent.com/max-sixty/worktrunk/main/README.md
- **Description**: Rust-written Git worktree manager built for running parallel AI coding agents, featuring copy-on-write (`target/` reflink) build-cache cloning and lifecycle hooks.
- **Date**: 2026-11-08
- **Current status**: Active, widely adopted (`12,549` GitHub stars)
- **Source file**: `raw/recency/2026-11-16-worktrunk-readme.md`
- **Verbatim quote**: "Worktrunk is a CLI for git worktree management, designed for running AI agents in parallel. Worktrunk's three core commands make worktrees as easy as branches. Plus, Worktrunk has a bunch of quality-of-life features to simplify working with many parallel changes, including hooks to automate local workflows & copy-on-write build caches."

### 4. Symposium (`symposium-dev/symposium` / `cargo agents`)
- **URL**: https://raw.githubusercontent.com/symposium-dev/symposium/main/README.md
- **Description**: Cargo subcommand (`cargo agents`, led by Niko Matsakis) that scans a Rust workspace's dependency graph and installs crate-matched skills, hooks, and MCP servers into AI coding agents.
