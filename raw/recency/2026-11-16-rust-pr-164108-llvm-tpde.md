Part of rust-lang/goals#802

This adds an unstable `-Z llvm-tpde` flag to rustc to opt into using the TPDE-LLVM codegen backend instead of LLVM itself. It takes several possible values:

* Without the flag, `rustc_codegen_llvm` operates as before.
* With `-Zllvm-tpde` or `-Zllvm-tpde=try`, it attempts to compile modules with TPDE, but falls back to LLVM if TPDE fails
* With `-Zllvm-tpde=only`, it attempts to compile modules with TPDE, and bails if TPDE fails (this is intended for development purposes)

This PR does not attempt to optimize TPDE's performance in any way. Previous experiments have run basic optimization passes even on -O0, which helped with wall time, or maintained a list of incompatible IR elements which cause the TPDE path to be skipped. I plan on adding those later.

## Stats

|  | `-Zllvm-tpde=only` | `-Zllvm-tpde=try` |
| --- | --- | --- |
| UI tests | 489 failed / 21873 passed (2.19% failed) | 29 failed / 22333 passed (0.13% failed) |

Most of the failing UI tests are to do with assembly, sanitizers, SIMD, and other things we already know TPDE doesn't support. I haven't triaged all the failures yet (not sure if this would be a good use of time at this point).

When compiling ripgrep with `-Zllvm-tpde=try`, I get a 3-4% wall time improvement, but a 17% icount improvement. I'm less confident in my measurement of the latter metric. 12 out of 1113 CGUs have to fall back to LLVM, with the rest using TPDE. All ripgrep unit tests pass.

Rollup merge of #164108 - TechnoPorg:unstable-tpde-flag, r=ZuseZ4

Add unstable `-Zllvm-tpde` flag to `rustc_codegen_llvm`

Part of rust-lang/goals#802

This adds an unstable `-Z llvm-tpde` flag to rustc to opt into using the TPDE-LLVM codegen backend instead of LLVM itself. It takes several possible values:

- Without the flag, `rustc_codegen_llvm` operates as before.
- With `-Zllvm-tpde` or `-Zllvm-tpde=try`, it attempts to compile modules with TPDE, but falls back to LLVM if TPDE fails
- With `-Zllvm-tpde=only`, it attempts to compile modules with TPDE, and bails if TPDE fails (this is intended for development purposes)

This PR does not attempt to optimize TPDE's performance in any way. Previous experiments have run basic optimization passes even on -O0, which helped with wall time, or maintained a list of incompatible IR elements which cause the TPDE path to be skipped. I plan on adding those later.

## Stats

|----------------|------------------------------------------|------------------------------------------|
| UI tests       | 489 failed / 21873 passed (2.19% failed) | 29 failed / 22333 passed (0.13% failed) |

Most of the failing UI tests are to do with assembly, sanitizers, SIMD, and other things we already know TPDE doesn't support. I haven't triaged all the failures yet (not sure if this would be a good use of time at this point).

When compiling ripgrep with `-Zllvm-tpde=try`, I get a 3-4% wall time improvement, but a 17% icount improvement. I'm less confident in my measurement of the latter metric. 12 out of 1113 CGUs have to fall back to LLVM, with the rest using TPDE. All ripgrep unit tests pass.
