Normally without this field, Cargo will only build the\n\n  ```\n  [lib]\n  ```\n\n  target from a dependency. This field allows specifying which target will be built, and made available as a binary at build time:\n  + ```\n    \"bin\"\n    ```\n\n    — Compiled executable binaries, corresponding to all of the\n\n    ```\n    [[bin]]\n    ```\n\n    sections in the dependency’s manifest.\n  + ```\n    \"bin:<bin-name>\"\n    ```\n\n    — Compiled executable binary, corresponding to a specific binary target specified by the given\n\n    ```\n    <bin-name>\n    ```\n\n    .\n  + ```\n    \"cdylib\"\n    ```\n\n    — A C-compatible dynamic library, corresponding to a\n\n    ```\n    [lib]\n    ```\n\n    section with\n\n    ```\n    crate-type = [\"cdylib\"]\n    ```\n\n    in the dependency’s manifest.\n  + ```\n    \"staticlib\"\n    ```\n\n    — A C-compatible static library, corresponding to a\n\n    ```\n    [lib]\n    ```\n\n    section with\n\n    ```\n    crate-type = [\"staticlib\"]\n    ```\n\n    in the dependency’s manifest.\n\n  The\n\n  ```\n  artifact\n  ```\n\n  value can be a string, or it can be an array of strings to specify multiple targets.\n\n  Example:\n\n  ```\n  [dependencies] bar = { version = \"1.0\", artifact = \"staticlib\" } zoo = { version = \"1.0\", artifact = [\"bin:cat\", \"bin:dog\"]}\n  ```\n* ```\n  lib\n  ```\n\n  — This is a Boolean value which indicates whether or not to also build the dependency’s library as a normal Rust\n\n  ```\n  lib\n  ```\n\n  dependency. This field can only be specified when\n\n  ```\n  artifact\n  ```\n\n  is specified.\n\n  The default for this field is\n\n  ```\n  false\n  ```\n\n  when\n\n  ```\n  artifact\n  ```\n\n  is specified. If this is set to\n\n  ```\n  true\n  ```\n\n  , then the dependency’s\n\n  ```\n  [lib]\n  ```\n\n  target will also be built for the platform target the declaring package is being built for. This allows the package to use the dependency from Rust code like a normal dependency in addition to an artifact dependency.\n\n  Example:\n\n  ```\n  [dependencies] bar = { version = \"1.0\", artifact = \"bin\", lib = true }\n  ```\n* ```\n  target\n  ```\n\n  — The platform target to build the dependency for. This field can only be specified when\n\n  ```\n  artifact\n  ```\n\n  is specified.\n\n  The default if this is not specified depends on the dependency kind. Tools that map paths embedded in artifacts back to local sources should consume unremap files instead of interpreting these prefixes.\n\nIf\n\n```\ntrim-paths\n```\n\nis not\n\n```\n\"none\"\n```\n\n,\nthen the following paths are sanitized if they appear in a selected scope:\n\n1. Path to a git dependency will begin with\n\n   ```\n   /cargo/git/<git source id>/<revision>\n   ```\n\n   , which replaces the checkout directory.\n\n   ```\n   <revision>\n   ```\n\n   is a prefix of the resolved commit ID recorded in the lockfile.\n5. Path to a path dependency outside the workspace will be replaced with\n\n   ```\n   /cargo/deps/<package name>-<package version>\n   ```\n\n   .\n6. Path into the build directory, for example\n\n   ```\n   OUT_DIR\n   ```\n\n   generated sources, will begin with\n\n   ```\n   /cargo/build-dir\n   ```\n\n   .\n\n```\n<registry id>\n```\n\nand\n\n```\n<git source id>\n```\n\nare opaque stable hashes of the dependency’s source.\n\nVendored copies of registry or git dependencies (via source replacement) are sanitized by their file location instead, like workspace paths when inside the workspace directory, otherwise like path dependencies.\n\n##### Unremap files\n\nWhen the\n\n```\nobject\n```\n\nscope is active and debuginfo is enabled,\nCargo writes an unremap file beside each final artifact.\nThe file is aimed at helping debuggers substitute sanitized paths back to local ones,\ne.g., via GDB’s\n\n```\nset substitute-path\n```\n\nor LLDB’s\n\n```\ntarget.source-map\n```\n\n.\n\nThe Rust toolchain provides\n\n```\nrust-gdb\n```\n\nand\n\n```\nrust-lldb\n```\n\nwrappers,\nwhich can load unremap files automatically.\nThis integration is currently unstable and available only in nightly toolchains.\nTo enable it,\nset\n\n```\nRUST_GDB_TRIM_PATHS=unstable\n```\n\nor\n\n```\nRUST_LLDB_TRIM_PATHS=unstable\n```\n\nrespectively.\n\nThe unremap file name ends with\n\n```\n.trim-paths.json\n```\n\n.\nFor example,\nyour\n\n```\nmy-app\n```\n\nexecutable would come with an unremap file named\n\n```\nmy-app.trim-paths.json\n```\n\nbeside it.\n\nThe unremap file is in JSON format:\n\n* ```\n  v\n  ```\n\n  carries the format version.\n* ```\n  rust_version\n  ```\n\n  and\n\n  ```\n  workspace_root\n  ```\n\n  are file-level metadata, namely the toolchain version and the workspace root.\n* ```\n  remaps\n  ```\n\n  is an array of records.
